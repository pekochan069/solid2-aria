## What Makes a Great Streaming Chat Experience

A chat transcript needs to follow new messages while the reader is at the end, and stay still when the reader scrolls back. The Solid scroller observes content and viewport changes to keep that behavior local to the transcript.

## MessageScroller

MessageScroller is a chat transcript scroller built for these behaviors. `MessageScrollerProvider` owns the scroll state and transcript-row behavior: opening position, streamed output, new-turn anchoring, prepended history, visibility, and scroll controls. `MessageScroller` is the styled frame that renders inside it.

MessageScroller is scoped to the scroll viewport. It does not own messages, AI state, transport, persistence, branching, or model state. Your product code stays focused on composing messages, markers, tools, attachments, and prompt inputs.

It gives you the scroll behavior that chat needs, without taking over the rest of the chat UI. And it stays fast, even in long conversations with rich markdown.

## Usage

```tsx
import { Message } from "#components/ui/message";
import {
  MessageScroller,
  MessageScrollerButton,
  MessageScrollerContent,
  MessageScrollerItem,
  MessageScrollerProvider,
  MessageScrollerViewport,
} from "#components/ui/message-scroller";
```

```tsx
<MessageScrollerProvider>
  <MessageScroller>
    <MessageScrollerViewport>
      <MessageScrollerContent>
        {messages.map((message) => (
          <MessageScrollerItem
            id={message.id}
            scrollAnchor={message.role === "user"}
          >
            <Message />
          </MessageScrollerItem>
        ))}
      </MessageScrollerContent>
    </MessageScrollerViewport>
    <MessageScrollerButton />
  </MessageScroller>
</MessageScrollerProvider>
```

`MessageScroller` fills its parent, so place it inside a height-constrained container.

```tsx
<div class="flex h-screen flex-col">
  <MessageScrollerProvider>
    <MessageScroller class="flex-1">{/* transcript */}</MessageScroller>
  </MessageScrollerProvider>
</div>
```

## Composition

```tsx
<MessageScrollerProvider>
  <MessageScroller>
    <MessageScrollerViewport>
      <MessageScrollerContent>
        <MessageScrollerItem>
          {/* a message, marker, or row */}
        </MessageScrollerItem>
        <MessageScrollerItem />
        <MessageScrollerItem />
      </MessageScrollerContent>
    </MessageScrollerViewport>
    <MessageScrollerButton />
  </MessageScroller>
</MessageScrollerProvider>
```

- **`MessageScrollerProvider`** — the headless root. Owns scroll state and the behavior props for opening position, auto-scroll, anchoring, scroll commands, and visibility tracking.
- **`MessageScroller`** — the styled frame. Lays out the viewport, content, and controls inside the provider.
- **`MessageScrollerViewport`** — the scrollable element. Receives native scroll events and preserves the visible row when older messages are prepended.
- **`MessageScrollerContent`** — the transcript container. Holds the rows and provides the live-region defaults for new messages.
- **`MessageScrollerItem`** — the transcript row boundary. Wrap every direct child of the content so the scroller can measure, anchor, preserve position, track visibility, and jump to it. An item can be a message, marker, typing indicator, separator, join/leave event, or "load earlier" row.
- **`MessageScrollerButton`** — the scroll control. Scrolls to the start or end of the transcript and is inert until there is content in its direction.

### Avoiding a Flash on Reload

Render the saved messages on the server when they are available. Keep the viewport height stable between the server and client renders. Store transcript state in the page or provider that owns the conversation.

### Loading Earlier Messages

Before prepending messages, record the viewport's `scrollHeight` and `scrollTop`. After the update settles, add the height difference to `scrollTop` to preserve the reader's position. The application owns fetching and pagination.

### Jumping to Messages

Use `useMessageScroller()` inside the provider. Its `scrollTo("start")` and `scrollTo("end")` methods move to either edge. For a specific message, find its stable DOM id inside `scroller.viewport` and call `scrollIntoView`.

```tsx
import { useMessageScroller } from "#components/ui/message-scroller";

export function JumpToLatest() {
  const scroller = useMessageScroller();
  return (
    <button onClick={() => scroller.scrollTo("end")}>Latest messages</button>
  );
}
```

### Tracking the Reader's Position

The visibility helper returns an accessor. Call `useMessageScrollerVisibility("end")` to track whether the reader has moved away from the end. Pass `"start"` to track the start.

```tsx
const awayFromEnd = useMessageScrollerVisibility("end")

<button hidden={!awayFromEnd()} onClick={() => scroller.scrollTo("end")}>
  Jump to latest
</button>
```

`useMessageScrollerScrollable()` returns an accessor that is true when the viewport can scroll. Read it in JSX. The context also exposes reactive `atStart`, `atEnd`, and `scrollable` properties.

## Performance

Native scroll listeners and observers update the scroller's small set of signals. Transcript rows retain their DOM identity as the scroll position changes. Keep expensive message rendering outside scroll handlers. Measure your application's actual transcript before introducing virtualization.

## Virtualization

The scroller renders real DOM rows. For very long transcripts, connect a Solid-compatible virtualizer to `MessageScrollerViewport` with a callback ref. The virtualizer owns visible row selection and measurement. Keep stable message ids, an accessible transcript label, and a way to load or reveal messages outside the mounted range.

The application owns the virtualizer integration.

## Accessibility

`MessageScroller` keeps the scroll container keyboard reachable and the transcript announceable without forcing a specific message UI.

`MessageScrollerViewport` is a labelled, keyboard-focusable scroll region by default. It uses `role="region"`, `aria-label="Messages"`, and `tabindex={0}`, so keyboard users can focus the transcript and scroll it directly.

`MessageScrollerContent` marks the transcript as a live region with `role="log"` and `aria-relevant="additions"`. New rows can be announced, but streamed text mutations do not have to be announced token by token.

```tsx
<MessageScrollerContent aria-busy={status === "streaming"}>
  {/* messages */}
</MessageScrollerContent>
```

Pass `aria-busy` while a turn streams if announcements should wait for the completed message row.

`MessageScrollerButton` renders a real button. When there is nothing to scroll toward, it sets `inert`, uses `tabindex={-1}`, and exposes `data-active="false"` so inactive scroll controls do not create extra focus stops.

## Unstyled

The generated component source separates viewport behavior from message appearance. Customize `MessageScroller`, `MessageScrollerContent`, and `MessageScrollerItem` to change the visual layout.

## API Reference

| API | Description |
| --- | --- |
| `MessageScrollerProvider` | Owns the viewport and scroll state for one transcript. |
| `MessageScrollerViewport` | Focusable native scroll region with resize and mutation observers. |
| `MessageScrollerContent` | Transcript log container. |
| `MessageScrollerItem` | Message row with optional `scrollAnchor`. |
| `MessageScrollerButton` | Scrolls to the start or end. |
| `useMessageScroller()` | Returns reactive state, `viewport`, `update`, and `scrollTo`. |
| `useMessageScrollerScrollable()` | Returns a boolean accessor. |
| `useMessageScrollerVisibility(direction)` | Returns an accessor indicating distance from an edge. |
